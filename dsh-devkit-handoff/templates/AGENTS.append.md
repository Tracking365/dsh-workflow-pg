# DSH DevKit 项目工作规范（待合并）

这是一组建议合并到插件仓库 AGENTS.md 的规则。保留已有有效规范，不得整体覆盖；更高优先级的环境安全规则仍然有效。

## 开发本项目

- 当前开发任务允许修改 DevKit 插件源码；不要顺带重构无关业务代码。
- 先核对锁定版本 DSH 的实际类型/源码，不编造接口，不使用 any 或假 Context 掩盖兼容问题。
- 优先保持一个组合包和清晰模块，避免提前拆微服务或引入第二个产品 launcher。
- 状态、快照、权限、审批、预算与成功判断由程序控制，不放进可随意改写的模型提示词。
- 不覆盖用户未提交修改，不改全局配置，不自行 push、merge、部署或发布包。
- 测试在临时 fixture 仓库运行，不把本插件源码目录误当成运行时的业务修复目标。
- 验收变化需说明理由，不能为了让测试通过而减弱安全标准、删除必要检查或放宽断言。
- 单元、原生 DSH、真实模型测试分列；未执行不等于通过，mock 不等于真实接入。
- API 密钥仅通过受信任配置引用，不打印、不写日志、不传给无关进程。
- 没有真实依据的模型 ID、provider 能力或平台支持，不作已实现声明。

## 未来业务执行器

- 只获得当前任务范围内的代码修改能力；不能修改 DevKit 控制面、宿主策略、数据库、冻结测试或验收证据。
- 同一任务只有一个代码写入者，审核只读。
- 确认 P0/P1 阻塞；P2/P3 待办不豁免验收失败；不确定高风险先补证或人工处理。
- 默认最多两次自动返修；取消、崩溃恢复不能产生双写或重置预算。
- 自动完成链路只进入待人工验收，不自动合并、发布。
